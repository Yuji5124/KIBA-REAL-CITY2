### 接続テストの結果
- **未接続。** MCP経由のシーン操作・メッシュ生成・GLB出力は**実行できていません**（このため「接続完了」とは報告しません）
- 代替として、クラウド上のBlender 5.2.2（Python版）で「メッシュ生成 → GLB出力 → 座標軸の確認」が成功済み

### 原因
Blender MCPサーバーはCodexにしか登録されておらず、このセッションが中継できるClaudeデスクトップアプリ側に登録がないため。

### 解決手順（どちらか一方）

**A. Claudeデスクトップアプリに登録する（このチャットから直接使える方法）**
1. PowerShellで `uvx --version` を実行し、uvが入っていることを確認（Codexで使えているなら入っているはず）
2. Claudeデスクトップアプリの設定ファイル `%APPDATA%\Claude\claude_desktop_config.json` に次を追加（既存の内容がある場合は `mcpServers` の中に `blender` を足す）
   ```json
   { "mcpServers": { "blender": { "command": "uvx", "args": ["mcp-for-blender"] } } }
   ```
3. Claudeデスクトップアプリを完全に終了して再起動
4. Blender 4.4を起動 → 3Dビューで `N` キー → 「BlenderMCP」タブ → サーバー開始（ポート9876）
5. **Codex側でBlenderを使っている場合は終了**（同じポートに2つのクライアントが同時に接続すると不安定になるおそれ）
6. このチャットで「接続した」と伝えてください。こちらでツール一覧を確認し、次の3点を実行して、成功した場合だけ「接続完了」と報告します
   - シーン情報の取得
   - テスト用メッシュ（立方体）の生成
   - GLBの書き出し

**B. Windows版Claude Codeを使う**
`claude mcp add blender -- uvx mcp-for-blender` で登録し、PC上のClaude Codeから作業する方法です。この場合は、このクラウドのセッションとは別の作業場所になります。

### 接続できるまでの制作方法
クラウドのBlender（Python版）でバッチ生成し、スクリプトはすべて `scripts/blender/` に保存します。PCのBlender 4.4ではGLBを読み込んで目視確認します。Blender 5.2で作った.blendは4.4で開けない可能性があるため、クラウドからは.blendを渡しません。MCPがつながったら、同じスクリプトをMCP経由で再実行して確認します。

## 3. 取得スクリプトの安全性確認

対象：`scripts/fetch/run_fetch_phase1.cmd`、`fetch_phase1_data.py`（v2に改訂）、`verify_phase1_data.py`（新規）

### 確認の過程で見つかり、修正した点
| # | v1の問題 | v2での対応 |
|---|---|---|
| 1 | OSMの編集用API（`/api/0.6/map`）を使っていた。OSMの方針では、このAPIは地図を**編集する人のためのもの**で、読み取り専用の利用には向かない | 読み取り専用の **Overpass API** に変更（2回の問い合わせのみ）。予備サーバーも用意 |
| 2 | 中断すると途中までのファイルが残り、次回「取得済み」と誤認するおそれ | `.part` に保存し、内容検証に合格してから名前を変える |
| 3 | 中身の検証なし（エラーページを画像として保存するおそれ） | PNG/JPEGのファイル署名と、OSMのXML構造を確認してから保存 |
| 4 | .cmdが `pip install` を自動実行し、Python環境を変更していた | 自動インストールを削除。足りない場合はメッセージを出して止まる |
| 5 | 保存先の検証なし | すべての保存先が `<新プロジェクト>\data\raw` の内側にあることを、通信前に確認 |
| 6 | 既存プロジェクトで誤って実行される危険 | フォルダ名が `-main` で終わる場合、または `CLAUDE.md` と `docs\phase0` が無い場合は実行を拒否 |
| 7 | 再試行なし | 429・504・通信エラーは最大4回まで、待ち時間を延ばしながら再試行。404は「データなし」として記録 |
| 8 | 前回の記録を上書き | 以前の `fetch_manifest.json` は日時付きの名前に変えて残す |

### 航空写真の扱い

### 失敗時の再実行
- 同じ .cmd をもう一度実行するだけです。取得済みで正しいファイルは再利用し、足りない分だけ取りに行きます
- 混雑（429）が続く場合は、30分ほど空けてから再実行してください
- 壊れたファイルがあっても**自動では消しません**。`verify_report.json` に記録されるので、そのファイルを手動で別の場所へ移してから再実行してください

### ダウンロード後の検証（`verify_phase1_data.py`）
1. 記録したSHA-256とファイルが一致すること
2. 予定した全リクエストが「取得済み」か「データなし」になっていること
3. 公園境界（relation/14273608）があり、外周が欠けずに閉じていること
4. 地域データに十分な数の地物（点1000以上・線100以上・園路50以上）があること
5. 標高タイルを読み取った値が妥当な範囲（−10〜60m）にあること。欠損の割合も記録する
