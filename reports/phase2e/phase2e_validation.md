# KIBA PARK REBUILD Phase 2E 検証レポート

## G6.2ファイル調査

対象の `Kiba_Park_Ohashi_G6.2_visual_details.glb` を読み取り専用で解析した。該当する名前の `.blend` ファイルは `KIBA-REAL-CITY-main/output` に見つからず、Blender MCPも使用していない。元GLBは変更せず、Phase 2EコピーからGLB scene extras中のAPIキー等の無関係な秘密メタデータ4項目だけを除いた。

- GLB 2.0、27メッシュ、2材質、356三角形。
- 構成: 主塔2、横梁1、ケーブル24。橋面メッシュは存在しない。
- メッシュから算出した範囲: X 73.868–89.600m、Y 0–60.000m、Z −236.018–−47.979m。Yを鉛直と解釈したとき、主塔の高さは設計参照値60m。
- GLB metadataのEPSG:6677投影原点 `[-2302.317826, -36106.717223]` はPhase 2Bと一致。GLBメッシュ位置はPhase 2Dのローカルメートル座標と同値の範囲にあるため、ビューアでは移動0m・回転0°・縮尺1.0の候補登録を使った。
- GLB metadataはローカル軸をZ-upと記すが、頂点範囲・塔の高さはThree.jsのY-up配置を示し、記述が矛盾する。この登録は画面上の位置整合であり、測量基準点による保証ではない。
- Phase 2Bのローカル変換式（E = E₀ + X、N = N₀ − Z）を適用すると、主塔中心の概算は西塔 `(-2226.318, -35974.717)`、東塔 `(-2214.318, -35974.717)` EPSG:6677。これはモデル座標からの変換値で、現地測量値ではない。

## OSM橋梁とPhase 2C移動面

OSM way `33976871` はPhase 2Bで2つのリボンに分かれ、Phase 2Cも2 runとして保持されている。両リボンの中心線合計は132.90m、端点間の最短すき間は16.616m。モデルのX-Z外接範囲は15.732m × 188.039mで、way `33976871` のrun stationの76.01%が外接範囲内だった。外接矩形による判定なので、ケーブルや塔が歩道と正確に重なる割合を示すものではない。

Phase 2Cのこのwayの推定高さは1.568–4.940m。元GLBにデッキ形状がないため、GLB橋面との高さ差、橋端と周辺園路との連続性は計測できない。見た目だけでデッキ面を足したり、この橋を通行可能にしたりしていない。橋梁13 runのうち、レビュー760区間・通行不可146区間はそのまま。移動判定コード、ナビゲーションJSON、橋面推定標高は変更していない。

## ブラウザー確認

Phase 2E専用Three.jsビューアをローカルブラウザーで開き、上空・橋梁地上・ロボット視点を確認する。G6.2は27の視覚メッシュとして表示し、ロボット移動はPhase 2Cの検査をそのまま使用する。

- 3視点を実ブラウザーで描画し、G6.2の塔・ケーブルと公園全域・地上園路・ロボットプロキシを確認した。
- 移動確認: 既存24mルートを再実行し、PASSと階段・急斜面・欠損・境界のBLOCKを確認する。

## 性能比較

同じローカルブラウザーの1秒HUDで確認した。FPSは測定中に変動するため、固定GPUベンチマークではない。

| 指標 | Phase 2D記録 | Phase 2E上空 | Phase 2E橋梁地上 | Phase 2Eロボット |
|---|---:|---:|---:|---:|
| FPS | 49.0–60.1 | 60.1 | 60.1 | 60.0 |
| draw calls | 19–26 | 19–53 | 50 | 50 |
| triangles | 541,188–599,384 | 541,188–599,740 | 599,306 | 599,306 |
| scene meshes | 24 | 51 | 51 | 51 |

上空視点の値は視錐台・LODで変わり、同じ画面でdraw 19 / 541,188 trianglesとdraw 53 / 599,740 trianglesを観測した。後者はPhase 2Dの最大記録よりdraw 27、356 triangles多い。橋梁地上・ロボット視点ではdraw 50、599,306 trianglesで、Phase 2D最大記録よりdraw 24多く、trianglesは78少なかった。scene meshesには視錐台外のGLBノードも含むため、draw callsとは別の値。

## 再生成と保護

Python構文、Node構文、Phase 2Eデータ検証を実施。Phase 1〜2D、raw DEM/OSM、元G6.2 GLB、Blenderシーン、`KIBA-REAL-CITY-main` は読み取りのみ。成果物とビューアはクローン内のPhase 2E用パスへ分離。外部有料APIは使用しない。

### 残る確認事項

1. 該当する元 `.blend` がないため、Blender側のobject transformや編集履歴は確認できない。
2. GLBのZ-up metadataとY-up頂点配置の矛盾を、元Blenderファイルまたは測量点で解消する必要がある。
3. デッキがGLBにないため橋面高の照合は未完了。地上ゲームで通行させるには、橋面測量またはデッキ付きの検証済みモデルが必要。
4. OSM run間の16.616mの空白は自動接続していない。
